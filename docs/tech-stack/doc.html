Teknisk dokumentation af tech-stacken

DOF.tool er en portal for feltornitologer: live-observationer fra DOFbasen, egne feltmeldinger og ture, lister, kalendere, fænologi, læring og showcase-moduler for DOFbasen og Netfugl. Den kører som en samling Docker-containere bag en reverse proxy og leveres som PWA i browseren og som Capacitor-app på Android/iOS.

Data og databaser

Tabellerne er delt i tre grupper (server/portal/dbgroups.py):

  • users – alt der handler om brugere: konti, lister, områder, alarmregler, feltmeldinger, kommentarer, kalendere, Netfugl-indhold, support.
  • observations – observationer, ture og observatører fra DOFbasen samt alle aggregater (artsdage, fænologi, regioner, vejr).
  • reference – arter, afdelinger, kommuner, lokaliteter m.m. findes i begge grupper, så joins mod dem er lokale.

En SQL-sætning må aldrig blande bruger- og observationstabeller; routeren afviser den. Data hentes i stedet i to trin (fx et tegnet områdes geometri slås op i brugergruppen og sendes som parameter til observationsforespørgslen).

Hver gruppe har én primary og nul eller flere replikaer. Replikaer tager en pg_basebackup af primary og streamer derefter WAL. En replika er enten til at aflaste læsninger eller kun til backup. Topologien ligger i db-admins register; api og worker henter den hvert 15. sekund og skifter forbindelser uden genstart. I legacy-tilstand kører alt på den samlede database (postgres), som også er kilde, når db-admin migrerer.

Objektlager

Fotos og lyd i feltmeldinger og ture gemmes i RustFS under obs/<uuid>.<endelse>. Adressen er /media/obs/<navn>, og api'et leverer filen efter login med Range-understøttelse (lydafspilning), ETag og privat cache. Bucket'en er aldrig offentlig. Uden S3_ENDPOINT ligger filerne på disken som før. Netfugl-fotos og læringsfiler ligger stadig på volumenet media.

Vedligehold: RustFS afløste MinIO, som ikke længere udgiver images og blev arkiveret i 2026. Filerne flyttes over én gang med tools/minio-to-rustfs.sh. Appen taler almindelig S3, så en anden tjeneste (Garage, SeaweedFS, Backblaze B2 …) kan overtage ved at ændre S3_ENDPOINT, S3_ACCESS_KEY, S3_SECRET_KEY og S3_BUCKET.

Sikkerhed

  • Login kontrolleres hos DOFbasen ved hvert login; adgangskoden gemmes ikke. Grænse for forsøg pr. obserkode og IP.
  • Sessioner i Valkey (sess:<token>), cookie HttpOnly, SameSite=Lax, altid Secure når PUBLIC_URL er https. Alle en brugers sessioner kan lukkes på én gang.
  • CSRF: ændrende kald kræver X-Requested-With eller Sec-Fetch-Site: same-origin.
  • Headers: streng CSP (scripts kun egne + hash), HSTS over https, X-Frame-Options: DENY, nosniff, Referrer- og Permissions-Policy. Uploads leveres med sandbox-CSP.
  • Klientens IP tages kun fra X-Forwarded-For, når kaldet kommer fra en betroet proxy.
  • Uploads: størrelsesgrænse, tilladte typer, tilfældigt filnavn; GPS og andre metadata fjernes, før filen gemmes.
  • SQL: kun parametre; sortering og visning fra whitelists.
  • Showcase-API'er: token gemt som hash, kun læsning, egne grænser pr. minut.
  • Netværk: db-admin, databasenoder og RustFS har ingen offentlige porte; db-admin har eget kodeord og begrænsning af forsøg. db-admin har adgang til Docker og skal aldrig udstilles mod internettet.

Persondata

Privatlivspolitikken ligger på /privatliv. Brugeren kan selv hente alle sine data som JSON (GET /api/me/export) og slette sin konto, hvilket også sletter uploadede filer, aktivitetslog og alle sessioner. Der er ingen analyse- eller sporingsværktøjer og kun én (nødvendig) cookie. Data sendes til tredjeparter som vist i diagrammet: DOFbasen (login, udtræk), OpenStreetMap (kortfliser, brugerens IP), Google FCM og browserens push-tjeneste (notifikationer).

Overvågning

Admin → Drift viser gateway, kø, job og lagerplads (disk, hver databasenode med største tabeller, objektlager, filer på disken og Valkey). db-admin viser hver nodes status og svartid. Sundhedstjek: GET /api/health.

Backup

Replikaer beskytter mod nedbrud af en node, ikke mod fejl i data eller tab af hele serveren. Brug derudover et natligt pg_dump af hver gruppe og en kopi af bucket'en, krypteret og gemt uden for serveren.
